# Technical Specification & Copilot Implementation Guide: Harness² Benchmark Analysis Dashboard

## 1. Overview & Objective
This document serves as the architectural and technical specification for building the **Harness² Benchmark Analysis Dashboard** in the `harness-benchmark` repository (`https://github.com/alulema/harness-benchmark`). 

The goal is to process, aggregate, and visualize evaluation runs generated by Google's Harness² framework across the three core benchmark suites:
- **LAB** (Legal Analysis Benchmark)
- **JobBench** (Professional Tasks)
- **WorkBuddy** (Code and Office Automation Tasks)

The dashboard enables interactive filterable views, comparative analysis (e.g., Gemini vs. Claude, Sequential vs. Parallel execution, $k$-budget convergence), and exportable metric insights.

---

## 2. Framework Context & Data Flow
Harness² outputs execution logs as structured JSON files inside the `runs/` directory upon completing evaluations. 

### Core Metrics & Data Extracted:
- **Accuracy & Delta Improvements ($\Delta$):** Base vs. Optimized harness score ($k=1 \dots K$).
- **Component Adoption Frequencies:** Percentage of proposed modifications adopted in `System Prompt`, `Memory Guardrails`, and `Tool Guidance`.
- **Convergence Rate:** Number of iterations ($k$) required before no further mutations pass the `Probe` phase.
- **Execution Cost & Latency:** Parallel vs. Sequential run performance metrics.

---

## 3. Tech Stack & Architecture

### Data Processing Pipeline (Python Engine)
- **Parser Script:** `scripts/parse_harness_runs.py`
- **Output Artifact:** `public/data/benchmark_summary.json` and `public/data/benchmark_summary.csv`
- **Libraries:** Pandas, Pydantic (for JSON schema validation).

### Dashboard Frontend
- **Framework:** Astro 4.x / 5.x with React Integration (`@astrojs/react`)
- **Styling:** Tailwind CSS, Lucide Icons
- **Visualizations:** Recharts or D3.js (Bar charts, Scatter plots for convergence, Radar charts for domain strengths, Line charts for score deltas).
- **Data Export:** CSV generation and SVG/PNG chart exporter.

---

## 4. UI Components Structure (`src/components/benchmark/`)

1. **`BenchmarkDashboard.tsx`**: Top-level container component with global state filters (Benchmark, Execution Mode, Model, Budget $k$).
2. **`FilterToolbar.tsx`**: Interactive controls to slice data by domain (LAB, JobBench, WorkBuddy), model provider (Gemini, Claude), and run mode (parallel/sequential).
3. **`KpiSummaryCards.tsx`**: High-level statistical callouts (+8.2pp avg improvement, Top mutation type, Avg convergence iteration).
4. **`ConvergenceChart.tsx`**: Line/Area chart displaying mean accuracy curve across iterations $k=0 \to K$.
5. **`ComponentAdoptionChart.tsx`**: Bar chart showing which harness components (`System Prompt`, `Memory`, `Tool Guidance`) had the highest adoption rate per benchmark.
6. **`ModelComparisonChart.tsx`**: Comparative visualizer for LLM performance deltas before and after Harness² optimization.
7. **`RunDetailsTable.tsx`**: Searchable and paginated table listing raw evaluation traces with drill-down modals.

## 6. Data Model Definition (`src/types/benchmark.ts`)

```typescript
export type BenchmarkType = 'LAB' | 'JobBench' | 'WorkBuddy';
export type HarnessMode = 'parallel' | 'sequential';
export type LLMModel = 'gemini-1.5-pro' | 'gemini-2.0-flash' | 'claude-3-5-sonnet';

export interface HarnessRunSummary {
  runId: string;
  benchmark: BenchmarkType;
  model: LLMModel;
  mode: HarnessMode;
  maxK: number;
  baseScore: number;
  finalScore: number;
  improvementDelta: number;
  convergedAtIteration: number;
  adoptedComponents: {
    systemPrompt: number;
    memory: number;
    toolGuidance: number;
  };
  scoreHistory: number[]; // Scores at k = 0, 1, 2...
}

export interface BenchmarkAggregateData {
  totalRuns: number;
  avgImprovement: number;
  runs: HarnessRunSummary[];
}
```

## 7. Python Data Parser (`scripts/parse_harness_runs.py`)

The script must scan `runs/**/*.json`, extract the `propose-probe-compose` trace logs, compute aggregate metrics, and generate the static `benchmark_summary.json` file for frontend consumption.
